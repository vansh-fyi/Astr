## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer shell → Cloudflare D1 | wrangler d1 execute with --remote flag; SQL generated from trusted internal binary data |
| developer shell → Cloudflare R2 | upload_to_r2.py using env-var credentials; S3-compatible API |
| Cloudflare D1 → Worker | Internal Cloudflare binding; no public trust boundary |
| Worker → app client | HTTPS response; bortle/sqm/ratio JSON from D1 query |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Tampering | D1 SQL import — SQL injection via generated chunks | accept | export_zones_to_sql.py generates values from trusted struct-unpacked binary, not user input; no injection surface |
| T-02-08 | Information Disclosure | R2 credentials in env vars | mitigate | Credentials set as env vars only, never committed to git; upload_to_r2.py reads via os.environ.get(); .env not in git |
| T-02-09 | Elevation of Privilege | wrangler --remote flag executing against production D1 | accept | Production database holds only public satellite radiance data (no PII, no secrets); worst case is corrupted zone data, recoverable by re-import |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages; wrangler used from cloudflare/node_modules (already installed) |
</threat_model>
